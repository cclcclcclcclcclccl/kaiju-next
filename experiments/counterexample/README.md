# 技术小样：寻找可回放的规则反例

这是方向筛选阶段的合成算法实验，不是参赛产品，不代表已锁定游戏方向。

## 运行

环境：本轮使用 Node.js v24.16.0，无第三方依赖。

在仓库根目录执行：

```powershell
node --test experiments/counterexample/core.test.mjs
node experiments/counterexample/run.mjs
```

## 检查的问题

人工定义一个明确契约：没有外部奖励、其他库存恢复原状的闭合交易/制造链，不应净增金币。

样例初始 4 金币；4 金币买 2 木材，2 木材制造 1 刀剑，刀剑卖 5 金币。广度优先搜索应发现买入→制造→卖出的三步反例，且输出可重新执行的完整资源轨迹。

把售价改为 4，先重放旧反例，再在最大 12 步、最多 10,000 个状态的边界内重新搜索。状态预算耗尽必须报告“不确定”，不能冒充“无问题”。

这里的盈利由合成规则故意设置，用来验证检测能力，不是一次真实用户 Bug，也不能当作比赛要求的真实 AI 调试链。某些游戏本来就希望制造获利，只有设计者明确禁止时此契约才适用。

## 结论边界

这是通用搜索方法的原创小实现，不宣称发明广度优先搜索或游戏形式化验证。它只能证明这个受限模型的部分可行性。

还缺自然语言规则提取、复杂意图表达、真实设计者需求、同类产品深入对比、可视化交互、API 接入、持久化和完整产品验证。不能把“给定边界内未发现反例”写成“绝无漏洞”或“已实现自动游戏平衡”。
