# v0.18 图标、出装明细与逐手 BP

日期：2026-10-19。本轮回应图片与比例条表达、装备栏位和完整出装、人工/人机逐手 BP、不足五人的体系适配。

## 检查入口

- **英雄图鉴 → 任意英雄**：技能、官方出装、铭文图标；公开统计的召唤师技能、克制与组合英雄图标。
- **英雄图鉴 → 实际出装统计**，或 **装备与版本 → 装备出场率 / 胜率**：单件总统计、第 1–6 装备栏热门装备、常见六件套。
- **阵容备战 → 红蓝双方 · 逐手 BP**：选规则和操作模式，开始演练。点头像后确认，可操作双方或只控制一方；支持暂停、接管、撤回和恢复。
- **体系练习**：选择自己和已共享英雄池的好友，生成所选人数的协作方案。支持 1–5 人；四人用于约练/自定义，不表示游戏排位允许四排。

## 真实来源

重新读取腾讯 133 位英雄公开 JSON，通过真实技能 ID 与名称建立 541 个技能图标映射，没有按数组位置猜 ID。原始响应和摘要在 `evidence/visual-bp-v018/official-media/`。

786 个图片地址经过文件头与 SHA-256 校验，保存在 `public/media/catalog/`。这是地址数，重复图片共享文件，并非独立图片文件数。来源记录在 `media-cache-manifest.json`。官网部分 `.jpg` 实际返回 PNG，文件按真实类型存储。本地图片失败再尝试原地址或已核对的装备回退资源，最后显示文字占位；失败不抹掉统计。

解析器现在保留原本被丢弃的 `topItemsBySlot`、`topFullBuilds` 和 `summonerSkills.skillIcon`。旧缓存从同 SHA-256 的原始响应恢复这些字段，不改写查询日或获取时间。

装备栏位**不等于购买顺序**。接口返回每栏热门装备，不是全部装备与全部栏位的完整交叉表。实查网站前端将完整出装 `frequency` 按百分比显示，本项目同样保留该单位；分母尚未独立核验。完整出装没有公布整套胜率，保持未知。

胜率条统一 0–100% 刻度，保留数值，颜色分为低于 48%、48%–50%、50%–52%、至少 52%。这是阅读辅助，不是替代梯度算法。

## BP 参考与实现

实际访问 https://tianyuanzhiyi.com/bp ，打开蓝方 Ban1 头像选择器，选择廉颇，观察进入红方 Ban1，并执行撤销。截图及公开脚本证据在 `evidence/visual-bp-v018/reference/`。小程序工具页的“英雄推荐”是上传截图流程，不能与网页 BP 混淆。

网页展示 BO3/5/7/9、交换红蓝方与分阶段选禁。本轮实现**单局**，不声称实现整场 BO。

- 20 手：蓝禁、红禁、蓝禁、红禁；蓝选、红选、红选、蓝选、蓝选、红选；红禁、蓝禁、红禁、蓝禁、红禁、蓝禁；红选、蓝选、蓝选、红选。
- 16 手：双方各禁三位，再按 1–2–2–2–2–1 选人。
- AI 是独立 Worker 中的极大极小搜索，新增显式选禁序列，使第二禁用阶段参与搜索。每手最多六候选、最多四手前瞻，保留节点数、预算限制与实际完成深度。不是全部棋树穷举或训练完成的职业模型。
- 暂停、撤回、重开、切模式、离开页面终止旧 Worker；过时结果不能落子。撤回后暂停，防止 AI 立刻重下。
- 演练独立于原备战阵容。“带入备战”明确指定红/蓝为我方。当前浏览器保存并校验恢复，刷新后 AI 暂停；可导出逐手 JSON。
- 完成后的结构评分：基础 40；前排/开团/法术/物理每项 +10；官网搭配或针对每条 +3，受克制 −4；限制在 0–100。权重公开但未经比赛结果校准，**不是实战胜率**。既有教练面板仍支持个人档案和好友分工推演；新的简明结构评估不冒充个人表现模型。

## 部分成员的体系

搜索允许空缺角色，只给已选成员分配英雄，一人一个、不重复英雄和分路。评分均值按真实成员数量计算。没有补造另外几位队友；最多给三份候选，未证明全局最优。
