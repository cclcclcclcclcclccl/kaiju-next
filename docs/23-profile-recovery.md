# v0.15：档案冲突保护与英雄池备份恢复

日期：2026-10-14。本轮优先完善真实玩家记录的可靠保存，不新增未经验证的 BP 能力或统计数值。

## 已完成

- 手动档案、导入后保存、截图核对保存改用 `/api/pro/profile-save`。事务内比较客户端读取的原档案和当前保存档案；不一致返回 409，不覆盖服务器记录。
- 冲突时保留当前页面草稿和截图识别结果，不自动重试覆盖。玩家可导出当前草稿，再明确选择“读取已保存版本（替换当前草稿）”。刷新或离开页面仍可能丢失尚未保存的草稿，导出功能不是自动草稿备份。
- 档案保存及截图识别期间锁定同一编辑区，避免请求处理中继续输入而被刷新结果覆盖。
- 英雄池可选择本站导出的 `kaiju-pool-backup-v1` 文件，校验大小、英雄 ID、标签及重复记录；先预览，再确认补入。
- 恢复操作只补入缺失英雄；已有熟练度保留。预览后其他页面添加英雄也不会被覆盖。服务端重新校验数据并记录恢复历史。
- 英雄池备份仅含自选英雄及标签。详细战绩已有独立档案导入导出；复盘图片、对局手记等尚未纳入统一备份。
- 更新状态说明区分“读取成功”和“来源数据属于今天”，纠正旧入口名称。

## 本次真实来源检查

查询日为 2026-10-13，实际检查于 2026-10-14。大众分段、巅峰1350+、顶端排位均返回此前相同查询的旧缓存（各135条，包括形态记录）；巅峰千强成功更新133条。旧缓存保留原获取时间和来源更新时间，不伪装为本轮新数据。详情见 `evidence/profile-recovery-v015/source-status.json`。

## 验证与边界

核心测试验证档案原子比较、账号隔离、过期版本拒绝、恢复保留熟练度及非法输入拒绝。浏览器验证两个页面分别编辑、冲突后草稿导出、明确重新读取、实际备份导出再导入、恢复后刷新保留，以及原截图 OCR 流程。

生产个人记录只读核对；所有写入测试使用独立测试库。升级前复制数据库，升级后比较原表记录。旧验收截图按备份恢复，本轮输出另行归档。

兼容旧客户端的 `/api/pro/profile` 全量接口仍保留，不能宣称所有外部写入都具有冲突保护。当前没有跨设备云同步、自动草稿恢复或整库用户级恢复功能。CAS 比较完整档案，不自动合并两个页面对不同字段的修改，以避免默默混合不同统计范围。
