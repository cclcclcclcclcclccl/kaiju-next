# 官方公开数据核验与接入 · v0.7

核验日期：2026-10-12。结论：**确实存在无需登录的腾讯官方英雄统计数据入口，已接入开局 NEXT；本次找到的是有覆盖限制的公开分享榜。** 此前“没有授权接口就无法获取官方统计”的判断过于笼统，已更正。未确认天元之弈实际使用哪个来源，不能由本次发现推断其后台实现。

## 可复核的官方来源

| 来源 | 本次实际结果 | 适用范围 |
| --- | --- | --- |
| [王者营地英雄热度榜](https://camp.qq.com/h5/webdist/hero-rank/index.html) | 独立、未登录的 Edge 页面成功展示三率、热度及更新时间 | 所有段位、巅峰赛 1350+、顶端排位；每个分段分路本次返回 10 条 |
| [官网赛事数据](https://pvp.qq.com/matchdata/index.html) | 公开赛事列表和 2026 年 KPL 年度总决赛英雄汇总均返回业务成功 | 本次汇总 83 个英雄条目；赛事胜率、选禁次数与选禁率，不能替代排位数据 |
| [官方英雄目录 JSON](https://pvp.qq.com/web201605/js/herolist.json) | 已有官方资料采集链路 | 133 位目录、技能与官网定性搭配/克制资料；不包含所需的完整分段三率 |

官方热度榜加载的公开脚本：

`https://camp.qq.com/h5/webdist/hero-rank/static/js/main.807f0b35.js`

脚本明确区分完整榜 `/gametoolbox/hero/getdetailranklistbyid` 和分享榜 `/gametoolbox/hero/getsharepagedetailranklistbyid`。以下请求使用分享榜，不发送 Cookie、Authorization、用户 ID 或登录令牌：

```http
POST https://kohcamp.qq.com/gametoolbox/hero/getsharepagedetailranklistbyid
Content-Type: application/json
kohDimGender: 2

{"cSystem":null,"h5Get":1,"rankId":0,"position":2,"segment":3,"eId":null}
```

`segment`：1 所有段位；3 巅峰赛 1350+；4 顶端排位。`position`：0 全部分路；1 对抗路；2 中路；3 发育路；4 游走；5 打野。请求值来自官方网页定义。完整榜匿名实测返回 `-30314 / 登录态参数不全`，没有继续使用或寻找他人的凭据。

上述请求实际返回 `returnCode: 0`，`data.updateTime: "20261011"`，`data.list` 为 10 条。海月这一条为：

```json
{
  "heroId": 521,
  "tRank": "T0",
  "winRate": 0.4988,
  "showRate": 0.059,
  "banRate": 0.8006
}
```

接口使用 0–1 比例，界面转换为胜率 49.88%、登场率 5.90%、禁用率 80.06%。`T0` 保留为“官方热度”。原始响应见 [official-response-peak-mid.json](../evidence/official-public-data/official-response-peak-mid.json)，官方页面截图见 [official-page.png](../evidence/official-public-data/official-page.png)。

## 实测覆盖与口径

| 官方分段 | 本次核验分路数 | 返回记录数 | 去重后的官方英雄 ID 数 |
| --- | ---: | ---: | ---: |
| 所有段位 | 5 | 50 | 40 |
| 巅峰赛 1350+ | 5 | 50 | 42 |
| 顶端排位 | 5 | 50 | 40 |

共 15 次分段分路查询、150 条记录，源更新日期均为 2026-10-11。不同分路会返回同一个英雄；官方有些形态使用单独 ID，例如李信相关的 50701、50702，不能将记录数称为独立英雄总数。官方新 ID 即使暂不在本地资料目录中，仍保留姓名和统计，不强行映射或丢弃。

官方网页的说明：T 等级代表使用热度，由登场率、胜率、Ban 率综合计算；顶端排位代表每日全网平均段位最高的前 10 万场对局。因此官方热度与我们打算验证的“适合谁、什么阵容、什么条件下使用”的强度评分不是同一个指标。

本次响应未提供英雄样本量、游戏版本、统计起止日期或明确的选禁分母。`updateTime` 只能称官方更新日期，不能据此断言三率仅统计该日。分路参数是官方榜单的筛选条件，也未证实三率只统计该分路对局。当前不据此生成置信区间、BP 总率、自研强度等级或 BP 版本评分。

官网脚本另定义了胜率/登场率/Ban 率排序参数 15/16/17。本次核验它们只改变默认排序字段，仍返回同一组 10 位英雄，没有补齐全榜。没有找到巅峰 1800+、万强、千强的匿名官方入口，不能把其他分段贴上这些标签。

## 已实现

- 分段梯度页自动读取当前支持分段、分路的官方公开榜，可切换、筛选、排序、重新读取和导出数据及来源；明确显示当前返回条数。
- 英雄详情读取同一分段分路的官方公开表现。未被本次公开记录覆盖时显示缺失，不以零胜率或弱势代替。
- 服务端固定请求腾讯官方地址，只允许验证过的分段和分路参数；不接收任意外部 URL。
- 30 分钟缓存、同一查询合并并发请求、12 秒超时、失败重试间隔，以及写入完成后替换缓存文件。重新启动可恢复上次成功数据。
- 业务错误、异常日期、重复 ID、越界比例或上游日期回退不覆盖有效缓存；失败时保留原获取时间并显式提示旧数据。首次请求失败时显示错误，不回填合成数据。
- 官方记录与个人导入快照分别保存。官方分享榜不会改写用户档案，也不会被误当作已满足口径要求的完整梯度样本。

实现入口：`server/pro/official.ts`、`src/player/pro/OfficialStats.tsx`。缓存位于当前 `PLAYER_DATA_DIR/official-ranks`；测试与正常服务使用不同目录。查看方式：打开本机应用 → 分段梯度 → 选择大众分段、巅峰 1350+ 或顶端排位；英雄页中也有官方公开表现。

## 其余核验结果与下一步

- 官方赛事公开接口：`GET https://prod.comp.smoba.qq.com/leaguesite/leagues/open`，及 `GET https://prod.comp.smoba.qq.com/leaguesite/league/hero/settle_list/open?league_id=20260004`。本次已验证和记录，没有混入排位梯度，也尚未增加赛事数据页面。
- 营地英雄详情中的 `getheropageinfo`、`getherofringedata`、`getheroextrainfo` 匿名请求均返回登录态参数不全。
- 公开旧爬虫指向的 `cgi.datamore.qq.com/datamore/smobahelper/v2/herorank` 本次返回 504；旧 PHP 榜单接口返回登录失效。它们是历史线索，不是当前可用来源。
- 全英雄、六分段自动统计仍未完成。补全时应继续核验官方新增公开页面，或在官方明确支持的登录/导出渠道中由账号本人取得数据。用户已打开天元之弈，但本次没有确认其数据来源或抓取实现。
- 个人英雄战力、巅峰分、游戏好友和私人对局记录没有因为接通公开英雄榜而自动获得同步能力。

本轮联网核验、页面检查和自动测试分别记录，避免将模拟网络测试说成真实源连通证明。来源脚本 SHA-256、参数、覆盖和失败接口见 [source-verification.json](../evidence/official-public-data/source-verification.json)。

## 本轮验证

28 项核心/接口测试、19 项 Edge 浏览器测试通过；构建、最终类型检查和格式检查通过。缓存故障测试覆盖进程重启、上游业务错误、异常响应、日期回退及冷却到期后的恢复，重复点击不会延后重试期限。

运行中的本机 v0.7 使用实际官方响应核对海月三率及 10 条覆盖数，电脑和 390px 手机的 axe 自动检查无检出违规、无页面横向溢出、无脚本错误。多列表格在手机卡片内部横向滚动；头像加载完成和导航动画结束后重新截图，已人工查看桌面、手机及英雄详情三张最终图。验收脚本 `node scripts/player/capture-official.mjs` 会阻止页面向本机业务 API 写入数据，不修改用户档案、好友或快照。

上述自动检查不等于完整可访问性认证，也不证明推荐效果优于其他产品。原有英雄资料脚本约 692 KB 的构建体积提示仍待处理。
