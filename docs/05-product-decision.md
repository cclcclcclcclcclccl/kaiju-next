# 衡局：当前开发主线与质量门槛

2026-10-11。用户授权按当前方案开始制作，最重要要求是极高质量。

## 决策

将“游戏经济规则的反例测试与修复验证”作为当前产品开发主线，暂名衡局。领域限于小型游戏/桌游的整数资源交易、制造与兑换，先提供一个完整可用且易验证的流程。

理由：前一轮核心小实验可行；原文允许游戏与交互方向；该范围可形成明确的约束、可重放反例和修改前后实验，适合展示意图控制与工程能力。尚无真实用户访谈和真实项目效果，因此不宣称已达到产品市场验证或算法原创突破。

如果真实用户并不需要这种验证，或深入竞品对比发现流程价值不足，仍须调整产品范围。

## 进一步公开资料核查

- https://modl.ai/ （2026-10-11，HTTP 200）主页宣称通过视觉观察和模拟输入进行游戏 QA，支持自然语言任务、错误报告、视频与日志。表明自动游戏测试本身不构成空白。
- https://docs.machinations.io/ （同日，HTTP 200）本轮可提取内容主要是导航，未获得深层功能细节，不能据此断言不支持反例搜索。

当前差异假设是针对已显式建模的经济规则，给出能逐步核对的短反例，以及相同约束和范围下的修改对照。不是任意商业游戏自动平衡或黑盒游戏测试。

## 第一版必须可用的流程

打开合成示例或导入规则 → 编辑资源和动作数值 → 明确验证约束和搜索边界 → 运行真实搜索 → 逐步回放 → 生成小范围参数修改建议 → 对照验证 → 保存实验与导出证据。

模型接入仅负责从文字提出结构化规则候选；必须由用户检查，不能直接执行任意生成代码。没有配置模型时明确显示状态，已有实验全流程仍可使用。

## 技术边界

状态为非负整数资源；动作成本和产出固定；无随机性、时间冷却、多人同时动作和隐藏状态。验证目标为在选定库存恢复初始值时，目标资源净增超过允许值。必须解释这只是设计者选择的一种约束，合理的生产盈利也可能被它标记。

使用有界广度优先搜索，给出在本模型下的最短见证；状态/时间预算耗尽返回不确定。有界未发现不等于全局无漏洞。修改建议只是经过相同范围检查的候选，不保证整体游戏平衡。

## 质量门槛

- 算法：合法轨迹、最短见证、预算边界、初始库存、分支与多次重复动作均有测试；不硬编码样例结果。
- 服务：服务端严格校验输入，限制载荷和搜索资源；本机绑定；密钥不上浏览器；SQLite 保存真实实验。
- 界面：主流程可发现，结果可解释，编辑后旧结果标记过期，运行与失败可见，键盘和窄屏可用。
- 复现：锁文件、环境模板、准确运行命令；无密钥示例与真实模型路径分开。
- 验收：类型检查、核心与 API 测试、浏览器端全流程测试、实际截图检查。
- 真实性：合成示例注明来源，模型未配置不伪装生成，产品与开发证据分开。
