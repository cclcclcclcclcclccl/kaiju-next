# v0.9：截图建池、梯度看板、资料库与 BP 模拟

日期：2026-10-12。参赛者：蔡晨霖，西安交通大学人工智能 2501 班。

本轮响应用户提出的截图录入、职业级 BP 目标、参考天元之弈梯度、持续版本更新、装备、皮肤和时长胜率要求。状态是可检查的本机增量版本，不能视为所有要求均已完成。

## 玩家现在可以怎样使用

1. 打开“玩家档案”：默认看截图入口，详细表单已折叠。按累计英雄战绩、英雄战力、可选巅峰赛页面逐张上传。识别英雄与字段后核对，选择采用项，确认保存。低置信度、重复冲突或范围冲突不默认采用。记录直接参与现有英雄池、个人推荐、BP、好友体系适配。
2. 打开“分段梯度”：默认按层级展示头像。可切换“官方热度”与“开局综合梯度”，支持分路、英雄搜索、详细表格和直达图鉴。未知统计不归入弱势层。
3. 打开“阵容备战”：原有教练搜索继续使用选手英雄池；展开“BP 模拟训练场”可用固定种子完成双方十手选人，检查重复、禁用冲突和分路覆盖，导出模拟记录，不覆盖当前阵容。
4. 打开“装备与版本”：装备搜索、分类、最多三件对比；皮肤按英雄/名称/品质检索；正式服与体验服公告分开。英雄图鉴增加皮肤、版本追踪章节。

皮肤目录质量处理：两条记录把“时之魔女”“大圣娶亲”写入英雄名称字段，未能按官方英雄名可靠映射，跳过并记录警告；“黄金射手座”同名同 ID 重复去除一条；刘禅的“绅士熊喵”“英喵野望”共享 ID，按英雄与名称区分，不能只以官方 ID 去重。没有靠猜测修补所属英雄。

公告接口参数来自官网公开客户端脚本 `https://game.gtimg.cn/images/js/pvpcommon/api.js`，使用网站公开请求签名规则，不使用玩家账号凭据。公告正文返回 JavaScript 变量赋值，用正则提取后 JSON.parse，不执行返回脚本。服务端只请求固定官方域名。

营地匿名详细接口 `getheropageinfo`、`getherofringedata`、`getheroextrainfo` 实际返回 `-30314 登录态参数不全`；这不等于拥有登录态便必然能取到用户要求的全部字段。未接触私有游戏后台、用户令牌或他人账号。

额外核查官方攻略频道：3491/7534 返回 2026-09-29 的海月/马超调整情报；5010 的顶部记录为 2023 年；4925、4959 为 2021 年；6420 为 2024 年。旧频道没有被包装成“最新打法”。当前实现自动更新官方公告，不是全网攻略实时采集。

## 天元之弈观察与差异

- 2026-10-12 梯度页按 T0、T0.5 等分组，显示头像分数，红边高禁、蓝边低出，并注明“算法测试中”。开局借鉴层级看板与来源日期呈现，但没有复制其分数，T0.5 未在缺少自有阈值论证时照搬。
- 装备页 2026-10-11 抵抗之靴出场率显示 492.3%，暗影战斧 284.3%。其分母没有完成确认，不能截断为 100% 或解释成“选用概率”。装备选择还受双方购买、游戏时长、优势局购买偏差影响，不能把装备胜率当因果提升。
- 皮肤库显示 964 款，与官方本次目录 828 条不一致，不能用其中一个数字保证完整覆盖。
- 卢雅那页面明确标注 2026-10-11 单日：烈焰狂欢 94.4%，原皮 5.6%。已经以“第三方页面人工观察”形式出现在对应图鉴，保留日期、来源和未知样本范围，不生成伪造历史曲线，不称当前使用率。

参考截图位于 `evidence/data-upgrade/reference/`。它们只捕获用户已打开的小程序窗口，不包含微信聊天。

## OCR 的实际能力与限制

引擎为本地 CPU RapidOCR 3.10.0 / onnxruntime 1.31.0 / Pillow 12.3.0，当前机器已安装在 `data/ocr-venv`。另机运行 `npm run ocr:setup` 安装，需要 Python（本机 3.13）和联网下载依赖。没有模型 API 费用。

流程：限 PNG/JPEG/WebP、8 MB；Python 在内存解码与识别，限制像素和输出大小；返回文字、置信度和坐标；基于字段别名、同一行或相邻位置提取数字；前端明确核对英雄、累计/赛季/近期范围和数值。原图不持久化，保存数值及哈希摘要，OCR 文字置信度不当作数值准确率。核对页可修改截图数据日期，旧截图不必按今天记录。巅峰总系数与加成百分数不自动混用，历史最高巅峰分不写入赛季最高。

真实本地引擎与浏览器链路已通过合成中文样张，识别 230 场、57.83%、评分 9.1、当前战力 9500、历史战力 12000，核对保存后刷新仍保留，并影响英雄池。样张明确标注合成，未写入用户的实际数据库。真实游戏/营地布局、不同缩放与低清截图识别率尚未评测。赛季或近期场次大于已有累计场次时拒绝补出虚构总场数，先上传累计战绩或手动补录。

## BP 改进及其证据范围

原有候选按即时评价截断，会漏掉某些空缺分路。现在在候选宽度允许时先保留每条空路的最佳应对，再补充高分候选。继续使用有预算的迭代加深、极大极小、剪枝、个人准备度与阵容机制评估。

`npm run bp:evaluate` 在六个固定种子上比较旧截断与新覆盖策略。前三个标作开发案例，后三个为预设留出案例；每个策略各跑六场，共 12 场、120 次选人。对方按种子使用随机合法或一手贪心策略；每场仅两次练习禁用，非完整赛事禁用规则。

本次结果：12 场均无重复或禁用冲突、五路完整；留出案例我方每次搜索的平均候选分路数从 2.4 增至 3.0。这个指标是工程覆盖检查，且是本次实现直接针对的目标，不能推断获胜能力提高。没有训练神经网络、没有自动更新战术权重、没有职业比赛独立标签，也没有真实赛果或教练盲评。有限候选搜索不是职业级证明。

## 梯度算法边界

延用同分段同分路的收缩胜率、出场率、禁用率和满足完整覆盖时的可选战力/评价分；保留 Wilson 区间、口径校验、低样本待验证。没有新增未经验证的“更准确”权重。各分路独立百分位不等同于跨路强度差距。官方热度只使用原标签，不伪装成开局自研强度；缺样本、混合人群和不一致时间口径的记录不能晋升为正式梯度。

本机默认分段全部英雄第一定位视图实际覆盖 36/133 位官方热度；这是当前查询匹配结果，会随公开榜变化。完整目录仍为 133 位。

## 更新、缓存与复现

- `npm run resources:refresh`：人工触发官方资料获取、结构校验与核验摘要写入。
- 本机服务运行期间每 15 分钟检查装备、皮肤、公告；页面有检查更新按钮，缓存期内沿用本次结果。服务关闭后不会更新，不称实时抓取。
- 失败保留上次成功资料和原日期；无旧缓存则报错，不生成数据。缓存也经字段、重复 ID、链接域名校验。
- 获取时间、来源发布日期、版本生效时间各自区分。
- `npm run ocr:setup`、`npm run bp:evaluate` 提供可重复执行入口。浏览器测试的公开资源夹具固定在 `tests/fixtures/`，不依赖开发者忽略目录中的文件。
