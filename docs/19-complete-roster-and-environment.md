## 算法定义与理由

使用同一天完整133位总体观察。设P为出场率的并列中位百分位，B为禁用率的并列中位百分位，两者范围0–100。同值同分，只有一个样本时取50；筛选英雄或分路不改变比较总体和原分数。

```
P(x) = 100 × [小于x的记录数 + (等于x的记录数−1)/2] / (N−1)
W = clamp(总体胜率−50, −5, 5) × 出场率/(出场率+2.5)
S = clamp(0.55P + 0.45B + W, 0, 100)
```

胜率缺失时W为0，原始胜率仍为null。出场率使用百分数单位，例如2.5代表2.5%。T0≥90，T1≥75，T2≥55，T3≥35，其余T4。

选禁百分位刻画本批次相对优先级，降低绝对数值尺度差异的影响。来源胜率口径为全量人群、版本累计，因此只作最多±5分的背景修正；低出场记录的修正进一步减弱。这个抑制项是启发式参数，不是场次、贝叶斯后验或统计置信度。胜率高不意味着在千强必然强势；高禁用也可能反映体验、偏好和对手策略。

权重与阈值在v1中固定、公开，尚未经实战数据标定。暂不将此分数写入BP强度权重。原有合格快照的强度模型仍要求同口径胜率、样本量及足够覆盖，与本环境分分开标明。

## 参数敏感性与实际输出

出场权重分别取45%、55%、65%，禁用权重取其补数；胜率修正乘0、0.5、1，共9组。显示各组得分最小值至最大值，跨T档则提示“边界敏感”。该范围不是95%置信区间，也不覆盖所有潜在算法设定。

本批次输出：T0 13位、T1 18位、T2 26位、T3 27位、T4 49位；26位跨档。完整分数、分量与范围见 `evidence/data-continuity/environment-evaluation.json`。这证明算法可复算、缺失处理与敏感性可检查，不能证明它比天元之弈准确或已具备职业决策能力。

执行 `npm run tiers:evaluate` 可从随项目保存的原始观察重新计算报告；不访问网络、不修改玩家数据。

主要局限：百分位会放大接近且被四舍五入的低值差异；全英雄比较受到位置生态影响；未知选禁分母不能计算真实BP合并率或被禁后的条件出场率；高禁用低出场英雄可能被低估；累计总体胜率不能反映最近调整的即时效果。页面使用“环境参考”而非“真实强度”标签。

## 强度校准还需要什么

优先取得同分段、同位置、明确时间窗口的胜场与场次，以及明确选禁分母，再按位置拟合并检验强度模型。训练与验证必须按日期切分，避免用未来结果评估过去排名；与仅胜率、仅选禁等简单基线比较，评估后续胜率排序、跨日稳定性和样本不确定性。职业比赛决策还需要版本、赛制、选手英雄池与阵容交互数据，不能由公开总体榜单直接宣称达到职业水平。

本轮验证：核心行为测试、133位身份/证据完整性、并列排序与输入顺序不变性、缺失与真实零值区分、得分边界、参数范围；浏览器验证新旧日期切换、筛选分数不变、英雄详情身份与数据、手机溢出及可访问性。最终机器结果见 `evidence/data-continuity/validation.json`。
