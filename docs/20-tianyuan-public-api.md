# v0.12 天元之弈公开接口溯源与全英雄采集

核验日期：2026-10-14，北京时间。用户要求全程不得虚构数据，并继续追溯天元之弈数据源。本次已从公开网页与公开代码线索找到可匿名读取的天元之弈网站接口，完成实际采集、页面集成和同日官方交叉核验。没有取得或宣称取得腾讯私有后台。

## 数据源如何找到

公开项目 `MUNJayLee/Ban-Pick-Assistant` 的采集配置，以及 `tian1miao/-bp--ocr---` 的更新代码，均指向 `https://tianyuanzhiyi.com`。随后实际打开该站，标题、微信公众号“天元之弈助手”、QQ群号及页面内容与用户打开的小程序对应。网页正常加载时发出 `/api/herostats`、`/api/global/tier` 等请求，公开前端脚本定义了分段和详情路径。

来源链接：

- 网站：[天元之弈数据站](https://tianyuanzhiyi.com/)
- 完整数据页：[英雄数据](https://tianyuanzhiyi.com/heroes)
- 发布者梯度：[来源梯度](https://tianyuanzhiyi.com/tier)
- 线索：[公开采集配置](https://github.com/MUNJayLee/Ban-Pick-Assistant/blob/master/scripts/scraper/config.json)
- 独立核验源：[王者营地官方分享榜](https://camp.qq.com/h5/webdist/hero-rank/index.html)

所有实际采集请求只带 `Accept: application/json`，没有Cookie、登录令牌或第三方代码中的外部鉴权头；没有运行下载的第三方代码。公开项目中将梯度评分映射成“类似胜率”的做法没有采用。来源接口直接提供真实发布值，我们不进行这种替代。

网站明确自称独立第三方，声明所有数据来自公开对局，部分响应附带“引用麻烦注明出处233”。网页可访问、响应可核验不等于我们独立审计过其对局采样、清洗和后台采集方法，也不等于取得任意商业再发布授权。现有界面持续显示来源链接及第三方属性。

## 真实性核对及勘误

1. 读取同日王者营地三个分段五路的150条记录，按来源英雄ID匹配，包含形态ID。450个胜率/出场率/禁用率字段全部一致。证据：`discovery/official-crosscheck.json`及15份官方数据包。这是重合字段一致性证据，不能证明整个天元后台使用营地接口。
2. 与10月12日133位截图观察逐项比较：398个已知数值中的397个在一位小数范围内吻合；明世隐两侧均缺失。夏侯惇禁用率原图为0.0%，此前人工记录成0.1%，已纠正；同日API为0.04%，与原图显示一致。
3. 勘误保留原图、旧提交、前后值、理由和日期。原始截图未覆盖，修正记录为 `discovery/corrections.json`。历史环境分已重新计算，参数敏感条目由26变为29，五档人数不变。新版来源梯度直接读取发布者数值，不使用旧OCR排名。
4. 10月13日明世隐接口返回42.06%总体胜率；保留10月12日缺失，绝不跨日回填。

## 软件中查看

“分段梯度”默认进入“天元联网全榜”，可选择四个已验证分段、日期、分路、英雄和排序。千强可以切换“天元来源梯度”。点击英雄后可查询总体表现、位置和召唤师技能、皮肤、时长、出装与克制组合；独立接口的口径说明始终可见。源形态有单独ID时保留统计身份，图鉴与其他详情仍指向基础英雄。

“历史快照与官方榜”保留截图记录、原有快照、官方分享榜及开局环境算法，来源之间不混合。采集不修改玩家英雄池、好友、复盘和统计快照数据库。

## 持续维护和复现

本地服务启动时检查昨日四分段全榜及来源梯度，每轮完成后60分钟再检查。单个查询缓存1小时；打开英雄页按需读取过期数据。每个服务实例最多串行发起每秒1个请求，共用在途请求；没有对133位详情每小时全量重抓。关闭服务即停止任务，可用 `RANK_AUTO_REFRESH=0` 禁用背景任务。

首次失败显示缺失；已有缓存失败时只返回同一查询的旧包，并显示旧缓存警告，保持原日期与获取时刻。不同日期或分段不会互相填空；重复ID、错误身份、日期不符、越界比例、异常未来更新时间、响应过大均拒绝。原始响应按内容哈希归档，保存原始字节供核对。

```
npm run tianyuan:collect -- 2026-10-13
npm run tianyuan:collect -- 2026-10-13 --full
```

第一条检查4份全榜和1份来源梯度。第二条另读取133位英雄各5类详情，总670查询，按服务限速执行，不会因为取不到数据而调用示例兜底。输出在`evidence/tianyuan-public-api/<日期>`；工作缓存与原始响应在`data/tianyuan`。两类无日期接口在该目录中的存放位置仅表示采集任务归属，包内没有伪造日期。

仍未取得：巅峰1800+和万强的已验证完整入口、总体样本场次、明确版本号、原始对局全集及后台采集链。发布者指数和各类关联胜率不能直接证明英雄/装备因果强度，尚未接入BP评分。验证详情与真实页面检查见 `evidence/tianyuan-public-api/validation.json`。
