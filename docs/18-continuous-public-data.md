采集时发现微信旧窗口仍显示10月11日；从小程序菜单“重新进入小程序”加载后，数据日变为10月12日，页面更新时间为2026-10-13 08:46。重载会重新开启“隐藏低出场率英雄”，已再次关闭并留存证据。这解释了为何不能把旧窗口的日期当成来源最新日期。

两天的数据均没有跨日混合。单一分路快照中的名称及各百分比逐项对照原图；另建独立总体观察模型，人工核对剩余37位的多分路标签、截断名称和目录定位差异。五种元流之子打开详情核对身份，数值仍取同一天的列表，不混入详情中的单日统计。明世隐胜率显示缺失，未填0。两天接受数量不同，反映来源当天显示的分路标签与可识别记录不同，不表示英雄从目录消失。

页底重新核验：千强模式涵盖QQ双区各分路约1000名顶尖选手，胜率为全量人群含更低分段、版本累计；出场和禁用的分母未明确。数据不进入BP强度权重。新增的环境梯度 v1 仅描述选禁优先级，带有限的总体胜率修正、明确的来源口径及参数敏感性提示，不是已标定的强度结论。

## 自动更新何时运行

本地服务启动成功后，立即检查营地三个公开分段的五条分路。每轮完成后35分钟再检查，不需要先打开某个分路页面。请求逐个执行，与界面请求共用30分钟缓存及重复请求合并；服务关闭、电脑关机或休眠期间不保证执行，重新启动会再检查。没有创建Windows系统计划任务。

接口失败保留原缓存和原来源日期，更新面板区分成功/缓存/旧数据/未取得。每个来源日期、分段、分路及不同内容都保存独立历史文件，相同内容不重复归档；同日修订不覆盖旧观察。记录来源数据日、实际获取时间、最近检查完成时间，三者分开。

在“分段梯度”展开“数据更新”，可查看最近完成、下次计划检查、十五路的来源日期及状态。页面每分钟检查任务状态，发现新一轮完成时刷新当前官方榜显示。天元之弈明确标记尚未自动同步，不与营地自动更新混淆。

手动执行一次检查：`npm run ranks:refresh`。该命令本身不安排下一次任务，失败或旧数据会返回非零退出码。自动定时在正常服务中运行；可设置 `RANK_AUTO_REFRESH=0` 关闭。浏览器测试默认关闭真实后台更新，使用独立测试目录。

历史文件在 `data/official-rank-history`，缓存仍在 `data/official-ranks`；玩家数据库不变。网络未更新时没有声称数据“实时”。

## 页面改进

- 默认按来源日期选择可用批次，新日期优先；保留旧日期可手动选择。
- 最新133位总体记录和旧100位快照分别展示；最新96位单一分路标签子集另行保留供核对。总体记录中明世隐缺失胜率不补零。
- 全部分路视图优先显示来源实际收录的分路，例如旧批次张良为游走，不因为目录第一定位是中路就隐藏已有数据。详情沿用该分路。
- 导入后直接定位保存返回的批次ID，避免新内置批次遮住用户刚保存的历史数据。
- 更新状态表支持手机横向滚动和键盘访问。

## 验证与限制

验证包括：54项核心测试，更新串行与重入合并、十五路完整覆盖、同内容归档去重、失败数据不伪造日期、重启不伪报定时任务、停止任务后不再安排下轮；另有真实OCR导入、新旧批次切换、来源分路详情、手机无溢出与可访问性检查。最终结果见 `evidence/data-continuity/validation.json`。

未完成：天元之弈无人值守全榜采集、所有六分段统计、完整皮肤出场率和时长胜率、用同口径对局结果校准的强度梯度。连续滚屏工具只适用于当前已核验的窗口布局与同一张表，不能把任意截图借用别的表头。也没有宣称当前数据更准确于原发布者或BP达到职业水平。

完整总体数据：`examples/tianyuan-complete-observation-2026-10-12.json`。算法、覆盖率和未完成字段见 [全英雄覆盖与梯度算法](19-complete-roster-and-environment.md)。
