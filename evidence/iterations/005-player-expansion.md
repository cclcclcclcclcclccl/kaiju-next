## 真实失败与修复记录

- 最初浏览器临时 MediaRecorder 生成的 WebM 只有文件头，无法解码。改用项目内测试工具生成有明确“合成测试”标识的三秒 VP9 录像；普通测试直接使用固定夹具，不需安装编码器。
- 首次生成夹具的精简 FFmpeg 不支持 PNG 解码，报 Output file does not contain any stream；改用其支持的 JPEG 管道输入，夹具生成成功。
- 好友浏览器测试的 status 选择器同时选中了全局提示与档案提示。改为 main 范围，实际双账号接受、共享、选英雄和保存流程通过。
- 统计表打开英雄详情原先丢失分段/分路。传递所选上下文并加入跨页面回归。
- 新增跨分段测试的 getByLabel 精确匹配超时。统计下拉增加显式可访问名称，完整回归通过。
- 算法审查发现部分可选列可能使每位英雄采用不同权重；改为同批次合格英雄全部覆盖才启用辅助项。低样本退出正式参考群；过期数据退出 BP。
- 实际截图审查发现 video.readyState 足够但尚未播放出首帧时能保存黑图，先前只检查图片可见的测试未发现。增加实际帧检查与播放提示；浏览器验证播放后截图像素非黑，不再只验 DOM。
- 重新保存复盘会创建重复记录，改为按已有 ID 更新并检验账号所有权。取消达到数量后静默删除旧记录的逻辑。
- 长英雄详情关闭入口会滚出屏幕，改为固定头部并增加技能、表现、克制、攻略、刷野直达。
- 截图曾捕获手机导航退出动画的中间状态；截图等待/完成动画并固定页面滚动位置后复核，不把中间态当成最终界面。

## 实际结果

16 项核心/接口测试通过；13 项 Edge 浏览器测试通过；TypeScript/Vite 构建与 Prettier 检查通过。自动无障碍覆盖八种状态，均无检出的违规，各有需人工判断项目。十张桌面/手机实际截图无页面横向溢出、无脚本异常；官方 138 封面路径返回 404，记录为外部资源可用性缺口。

官方资料主体不依赖运行时抓取；全部英雄文本导致数据脚本约 692 KB，存在构建体积提示，尚未做按需加载。没有隐藏该提示。

证据：evidence/expansion/hero-fetch.json、browser-results.json、validation.json、accessibility*.json、live-check.json、screenshots/。工具生成的合成视频和算法示例只用于工程检查，不能证明真实游戏复盘或梯度准确性。

代码提交 e76f322 从新 Git 归档、空数据库复现成功，耗时 29.535 秒，包含依赖安装、构建、16 项核心测试和启动检查。使用已有 Node/npm 与缓存，不含浏览器套件。复现工具首次因旧版 PowerShell 误读无 BOM 的中文脚本而解析失败；改用当前 PowerShell 显式 UTF-8 读取后执行成功。结果见 evidence/expansion/reproduction.json。
