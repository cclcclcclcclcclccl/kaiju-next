## 实际修改

1. 默认统计表单，支持逐行和粘贴录入、预览确认、来源日期，保留 JSON。接受微信小程序出处、提供复制，拒绝可执行来源链接。新增搜索和指标排序、导出快照。
2. 体系核心英雄按不同成员分配；一个人不能占多个位置，缺少位置明确显示，默认排除正在练英雄。
3. 基于五个实际成员英雄池生成最多三份五路起始方案，有限搜索并重新评分，不重复英雄或成员，支持分工卡导出与进入 BP。
4. 新增公开参考访问证据、下一步资料清单、模型配置步骤与数据授权询问模板；准备 Git 忽略的资料目录。

## 发现的问题与修复

- 表格空字符串经过数字转换可能成为 0。解析器先检查格式，必填率为空时拒绝；未公布的场次保持缺失，不能伪造样本量。
- 只数“池里有几个英雄”不能证明多人能组成体系。使用不同成员约束匹配，加入一人不能同时承担多个核心位的测试。
- 刷新共享记录时每次都创建新的选择数组，会触发清空效果，使刚生成的方案消失。仅在成员实际变化时替换数组，并用浏览器验证结果持续显示及进入 BP。
- 没有任何可分配核心英雄时展示六块空结果冗余。改为一次说明与下方可选练习模板。
- 旧浏览器用例仍往 v0.4 证据目录写截图。把新版输出移入 refinement，恢复历史截图；新结果有独立版本记录。
- 最后核对发现“无法覆盖五个位置”对有限搜索结论表述过强，改为“暂未找到覆盖五个位置的方案”，不把搜索失败宣称为证明无解。公开参考文本固定原始字节，避免跨平台换行改变证据哈希。

## 检查与限制

20 项核心/接口测试、15 项 Edge 浏览器测试、构建通过。新增两条浏览器流程验证真实服务端保存和五个独立测试账号互相接受并共享，测试库与个人库隔离。10 个状态自动无障碍检查无检出违规，保留人工判断项。桌面与手机截图检查见本轮证据。

运行中的服务已更新为 v0.5.0，另外通过只读页面检查确认无脚本错误、无横向溢出、无失败请求。未把合成统计或测试账号写进生产个人数据库。

真实六分段自动源、官方个人数据同步、实战权重校准、真实视觉模型及整局理解、跨设备多人部署仍未完成。五人生成器尚无真实分段数据和敌方 BP，备战分不是胜率，不保证全局最优。正式比赛材料还未完成，不能用测试数量代替实战效果。
